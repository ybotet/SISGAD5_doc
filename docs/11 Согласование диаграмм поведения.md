# 11. Согласование диаграмм поведения
_(Coordinación de diagramas de comportamiento)_

---

## 1. Что такое согласование?
_(¿Qué es la coordinación?)_

Проверка того, что все диаграммы поведения (состояний, деятельности, последовательности) не противоречат друг другу.

_(Verificar que todos los diagramas de comportamiento no se contradicen entre sí.)_

---

## 2. Проверенные сценарии
_(Escenarios verificados)_

| #   | Сценарий                            | Диаграммы                                                   |
| --- | ----------------------------------- | ----------------------------------------------------------- |
| 1   | Диагностика и решение (тест решает) | Состояний, Деятельности (процесс 1), Последовательности     |
| 2   | Ремонт с материалами                | Состояний, Деятельности (процесс 1 и 2), Последовательности |

---

## 3. Проверка переходов
_(Verificación de transiciones)_

| Шаг (Деятельность)  | Изменение состояния   | Допустимо? (Диаграмма состояний) |
| ------------------- | --------------------- | -------------------------------- |
| Создать тикет       | → Открыта             | Да                               |
| Тест решает         | Открыта → Решена      | Да                               |
| Тест не решает      | Открыта → Проверена   | Да                               |
| Назначить работника | Проверена → Назначена | Да                               |
| Работа успешна      | Назначена → Решена    | Да                               |
| Работа с ожиданием  | Назначена → Ожидает   | Да                               |
| Решить ожидающее    | Ожидает → Решена      | Да                               |
| Закрыть тикет       | Решена → Закрыта      | Да                               |

**Результат:** Все переходы  **согласованы**.

---

## 4. Требования к поведению
_(Requisitos de comportamiento)_

| ID    | Требование                                                      |
| ----- | --------------------------------------------------------------- |
| BR-01 | Диагностика должна быть завершена максимум за 10 минут          |
| BR-02 | Нельзя закрыть тикет без диагностики                            |
| BR-03 | Материалы регистрируются после закрытия тикета                  |
| BR-04 | Состояние "Ожидает" только если clavePendiente = true           |
| BR-05 | Назначение работника требует роль Супервизор                    |
| BR-06 | Материалы регистрируются ПОСЛЕ закрытия тикета                  |
| BR-07 | Все критические изменения аудируются (пользователь, дата, ключ) |
| BR-08 | Конфликты версий → ошибка 409                                   |

---

## 5. Обработка ошибок
_(Manejo de errores)_

| Ошибка           | Код | Действие             | Идемпотентность |
| ---------------- | --- | -------------------- | --------------- |
| Данные невалидны | 400 | Отказ, сообщение     | Да              |
| Нет прав         | 403 | Отказ, сообщение     | Да              |
| Конфликт версий  | 409 | Отказ, перезагрузить | Да              |
| Ошибка БД        | 500 | Отказ, лог, откат    | Нет             |

---

## 6. Наблюдаемость
_(Observabilidad)_

**Логируемые события:**

| Событие                    | Данные                                 |
| -------------------------- | -------------------------------------- |
| Тикет создан               | id, клиент, пользователь, время        |
| Тест зарегистрирован       | id, результат, **ключ**, пользователь  |
| Работа зарегистрирована    | id, действия, **ключ**, пользователь   |
| Тикет закрыт               | id, время, **ключ**, пользователь      |
| Материалы зарегистрированы | список, количества, **ключ**, менеджер |

**Корреляционный ID:** `X-Request-ID` для сквозной диагностики.

## 8. Чек-лист согласованности
_(Checklist de consistencia)_

| Проверка                                                        | Статус |
| --------------------------------------------------------------- | ------ |
| Переходы в деятельности соответствуют диаграмме состояний       | Да     |
| Сообщения в последовательности соответствуют шагам деятельности | Да     |
| Роли в деятельности соответствуют акторам из прецедентов        | Да     |
| Терминальные состояния не имеют исходящих переходов             | Да     |
| Каждый BR имеет диаграмму и тест                                | Да     |
