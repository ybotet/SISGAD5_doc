# 16. Конкурентность и транзакции
_(Concurrencia y transacciones)_

---

## 16.1. Введение
_(Introducción)_

В данной практической работе анализируются транзакционно-критичные операции системы, определяются границы транзакций, уровни изоляции, механизм конкурентного контроля (оптимистическая блокировка), а также тесты конкурентности и диагностика блокировок.

_(En esta práctica se analizan las operaciones críticas para transacciones del sistema, se definen los límites de las transacciones, los niveles de aislamiento, el mecanismo de control de concurrencia (bloqueo optimista), así como las pruebas de concurrencia y el diagnóstico de bloqueos.)_

---

## 16.2. Выбор транзакционно-критичных операций
_(Selección de operaciones críticas para transacciones)_

| №   | Операция _(Operación)_                                   | Таблицы _(Tablas)_     | Почему атомарно? _(¿Por qué atómica?)_                      | Последствия частичного выполнения _(Consecuencias de ejecución parcial)_ |
| --- | -------------------------------------------------------- | ---------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | Закрытие заявки _(Cierre de ticket)_                     | `Ticket`, `Audit`      | Статус должен измениться только при успешной записи в аудит | Статус не соответствует аудиту                                           |
| 2   | Назначение техника _(Asignación de técnico)_             | `Ticket`, `Asignacion` | Техник не может быть назначен дважды на одну заявку         | Двойное назначение, конфликт данных                                      |
| 3   | Обновление запасов материалов _(Actualización de stock)_ | `Material`             | Списание материалов должно быть атомарным                   | Отрицательный запас, некорректный учет                                   |
| 4   | Регистрация расхода материалов _(Registro de consumo)_   | `Material`, `Consumo`  | Расход и списание должны быть согласованы                   | Списание без расхода или расход без списания                             |

**Всего:** 4 операции

## 16.3. Границы транзакций
_(Límites de transacciones)_

### 16.3.1. Операция 1: Закрытие заявки
_(Operación 1: Cierre de ticket)_

```sql
BEGIN; -- Начало транзакции

-- 1. Проверить текущий статус и версию
SELECT estado, version FROM Ticket WHERE id = 1;

-- 2. Обновить статус (только если версия не изменилась)
UPDATE Ticket 
SET estado = 'Cerrada', 
    version = version + 1,
    updatedAt = NOW()
WHERE id = 1 AND version = 1;

-- 3. Записать в аудит
INSERT INTO Audit (entity, entityId, action, userId, timestamp)
VALUES ('Ticket', 1, 'CLOSE', 123, NOW());

COMMIT; -- Конец транзакции
```

## 16.3.2. Операция 2: Назначение техника
(Operación 2: Asignación de técnico)

```sql
BEGIN;

-- 1. Проверить, что техник не превысил лимит (8 активных назначений)
SELECT COUNT(*) FROM Asignacion 
WHERE trabajadorId = 5 AND estado = 'Activa';

-- 2. Проверить версию заявки
SELECT version FROM Ticket WHERE id = 1;

-- 3. Обновить заявку
UPDATE Ticket 
SET estado = 'Asignada', 
    version = version + 1,
    trabajadorId = 5,
    updatedAt = NOW()
WHERE id = 1 AND version = 1;

-- 4. Создать запись о назначении
INSERT INTO Asignacion (ticketId, trabajadorId, fechaAsignacion, estado)
VALUES (1, 5, NOW(), 'Activa');

COMMIT;
```

## 16.3.3. Операция 3: Обновление запасов материалов
(Operación 3: Actualización de stock)

```sql
BEGIN;

-- 1. Проверить текущий запас и версию
SELECT stock, version FROM Material WHERE id = 1;

-- 2. Проверить, что списание не превышает запас
-- (выполняется в приложении)

-- 3. Обновить запас
UPDATE Material 
SET stock = stock - 10, 
    version = version + 1,
    updatedAt = NOW()
WHERE id = 1 AND version = 1 AND stock >= 10;

COMMIT;
```

## 16.3.4. Операция 4: Регистрация расхода материалов
(Operación 4: Registro de consumo)

```sql
BEGIN;

-- 1. Создать запись о расходе
INSERT INTO Consumo (ticketId, materialId, cantidad, clave, fecha)
VALUES (1, 1, 10, '7R', NOW());

-- 2. Обновить запас материала
UPDATE Material 
SET stock = stock - 10, 
    version = version + 1,
    updatedAt = NOW()
WHERE id = 1 AND version = 1 AND stock >= 10;

COMMIT;
```

## 16.4. Уровни изоляции
(Niveles de aislamiento)

### 16.4.1. Выбранный уровень изоляции
(Nivel de aislamiento seleccionado)

| Операция (Operación) | Уровень изоляции (Nivel de aislamiento) | Обоснование (Justificación)                   |
| -------------------- | --------------------------------------- | --------------------------------------------- |
| Закрытие заявки      | READ COMMITTED                          | Достаточно для предотвращения грязного чтения |
| Назначение техника   | READ COMMITTED                          | Конфликты обрабатываются optimistic locking   |
| Обновление запасов   | READ COMMITTED                          | Проверка stock >= cantidad в UPDATE           |
| Регистрация расхода  | READ COMMITTED                          | Две операции в одной транзакции               |

### 16.4.2. Риски и допустимые аномалии
(Riesgos y anomalías permitidas)

| Аномалия (Anomalía)                        | Допускается? (¿Permitida?) | Почему? (¿Por qué?)          |
| ------------------------------------------ | -------------------------- | ---------------------------- |
| Грязное чтение (Dirty read)                | Нет                        | READ COMMITTED запрещает     |
| Неповторяемое чтение (Non-repeatable read) | Да                         | Допустимо для данной системы |
| Фантомы (Phantom read)                     | Да                         | Допустимо для данной системы |

## 16.5. Конкурентный контроль (оптимистическая блокировка)
(Control de concurrencia - optimistic locking)

### 16.5.1. Механизм
(Mecanismo)

Для каждой таблицы, где возможны конкурентные изменения, добавляется поле `version`:

```sql
ALTER TABLE Ticket ADD COLUMN version INTEGER DEFAULT 1;
ALTER TABLE Material ADD COLUMN version INTEGER DEFAULT 1;
ALTER TABLE Asignacion ADD COLUMN version INTEGER DEFAULT 1;
```

### 16.5.2. Пример обновления с проверкой версии
(Ejemplo de actualización con verificación de versión)

```sql
-- Приложение читает запись (version = 1)
SELECT id, estado, version FROM Ticket WHERE id = 1;
-- Результат: id=1, estado='Abierta', version=1

-- Приложение обновляет, проверяя что версия не изменилась
UPDATE Ticket 
SET estado = 'Cerrada', 
    version = version + 1,
    updatedAt = NOW()
WHERE id = 1 AND version = 1;

-- Если rows_affected = 1 → OK
-- Если rows_affected = 0 → другой пользователь уже изменил запись
```

### 16.5.3. Обработка конфликта
(Manejo de conflictos)

```text
Ошибка 409 CONFLICT
Сообщение: "Запись была изменена другим пользователем. Пожалуйста, обновите страницу и повторите попытку."
```

### 16.5.4. Операции с мягкими гарантиями
(Operaciones con garantías suaves)

| Операция (Operación) | Тип контроля (Tipo de control) | Причина (Razón)             |
| -------------------- | ------------------------------ | --------------------------- |
| Создание заявки      | Мягкий (Suave)                 | Новые записи не конфликтуют |
| Чтение списка        | Мягкий (Suave)                 | Только чтение               |
| Отчеты               | Мягкий (Suave)                 | Не изменяют данные          |

## 16.6. Тесты конкурентности
(Pruebas de concurrencia)

### 16.6.1. Сценарии тестов (5 сценариев)
(Escenarios de prueba - 5 escenarios)

| №   | Сценарий (Escenario)                    | Описание (Descripción)                                           | Ожидаемый результат (Resultado esperado)        |
| --- | --------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------- |
| 1   | Два пользователя закрывают один тикет   | User A и User B пытаются закрыть Ticket #1 одновременно          | Только один успешен, второй получает ошибку 409 |
| 2   | Назначение техника на одну заявку       | Два супервизора назначают разных техников на один ticket         | Только одно назначение успешно                  |
| 3   | Списание материалов сверх запаса        | Попытка списать 100 единиц при запасе 50                         | Ошибка, запас не становится отрицательным       |
| 4   | Одновременное списание одного материала | Два пользователя списывают материал с запасом 100 (каждый по 60) | Только один успешен (60 + 60 > 100)             |
| 5   | Регистрация расхода без списания        | Транзакция прерывается после INSERT в Consumo                    | ROLLBACK, материал не списан                    |

### 16.6.2. Ожидаемые результаты
(Resultados esperados)

| Сценарий | Результат                                                                   |
| -------- | --------------------------------------------------------------------------- |
| 1        | rows_affected = 1 для первого, 0 для второго → ошибка 409                   |
| 2        | Первая транзакция обновляет ticket_id = 1, вторая видит estado = 'Asignada' |
| 3        | UPDATE no afecta filas (stock >= cantidad false) → ошибка                   |
| 4        | Первый UPDATE успешен, второй видит stock = 40 → ошибка                     |
| 5        | ROLLBACK, Consumo no se guarda, Material no se actualiza                    |

### 16.6.3. Как воспроизвести тесты
(Cómo reproducir las pruebas)

```bash
# Открыть два терминала PostgreSQL
# Терминал 1 (User A)
BEGIN;
SELECT version FROM Ticket WHERE id = 1; -- version = 1

# Терминал 2 (User B)
BEGIN;
SELECT version FROM Ticket WHERE id = 1; -- version = 1

# Терминал 1
UPDATE Ticket SET estado = 'Cerrada', version = 2 WHERE id = 1 AND version = 1;
COMMIT; -- Успешно

# Терминал 2
UPDATE Ticket SET estado = 'Cerrada', version = 2 WHERE id = 1 AND version = 1;
-- rows_affected = 0 (конфликт)
ROLLBACK;
```

## 16.7. Расширенные возможности SQL (опционально)
(Características avanzadas de SQL - opcional)

### 16.7.1. UPSERT (вставка или обновление)
(UPSERT - insert or update)

```sql
-- Если материал существует, обновляем запас; если нет — создаём
INSERT INTO Material (codigo, nombre, stock, version)
VALUES ('CBL-001', 'Кабель UTP', 100, 1)
ON CONFLICT (codigo) 
DO UPDATE SET stock = Material.stock + EXCLUDED.stock,
              version = Material.version + 1;
```

### 16.7.2. CTE для атомарного обновления
(CTE para actualización atómica)

```sql
WITH updated_stock AS (
    UPDATE Material 
    SET stock = stock - 10,
        version = version + 1
    WHERE id = 1 AND stock >= 10
    RETURNING id, stock
)
INSERT INTO Consumo (ticketId, materialId, cantidad, fecha)
SELECT 1, 1, 10, NOW()
WHERE EXISTS (SELECT 1 FROM updated_stock);
```

## 16.8. Диагностика блокировок и взаимных ожиданий
(Diagnóstico de bloqueos y deadlocks)

### 16.8.1. Просмотр активных блокировок
(Ver bloqueos activos)

```sql
SELECT 
    locktype,
    relation::regclass,
    mode,
    granted,
    pid,
    query
FROM pg_locks
JOIN pg_stat_activity ON pg_locks.pid = pg_stat_activity.pid
WHERE NOT granted;
```

### 16.8.2. Метрики и логи для обнаружения проблем
(Métricas y logs para detectar problemas)

| Метрика (Métrica)       | Порог тревоги (Umbral) | Действие (Acción)       |
| ----------------------- | ---------------------- | ----------------------- |
| Конфликты версий (409)  | > 10 в час             | Уведомление админа      |
| Длительность транзакции | > 5 секунд             | Оптимизация запроса     |
| Количество ретраев      | > 3 на операцию        | Проверка конкурентности |

## 16.9. Метрики и критерии оценки корректности
(Métricas y criterios de evaluación de corrección)

| Метрика (Métrica)               | Описание (Descripción)               | Целевое значение (Valor objetivo) |
| ------------------------------- | ------------------------------------ | --------------------------------- |
| Доля конфликтов версий          | (число_409) / (общее_число_запросов) | < 5%                              |
| Средняя длительность транзакции | AVG(commit_time - begin_time)        | < 500 мс                          |
| Число ретраев                   | Среднее число повторных попыток      | < 2                               |
| Процент успешных ретраев        | (успешные_ретраи) / (всего_ретраев)  | > 90%                             |

**Пороги деградации:**

| Метрика                 | Порог   | Действие                                          |
| ----------------------- | ------- | ------------------------------------------------- |
| Конфликты версий        | > 20%   | Увеличить поле version, оптимизировать транзакции |
| Длительность транзакции | > 2 сек | Добавить индексы, оптимизировать запросы          |
| Число ретраев           | > 5     | Проверить логику приложения                       |

### 16.10.2. Требования к индексам
(Requisitos de índices)

```sql
-- Для поиска заявок по статусу
CREATE INDEX idx_ticket_estado ON Ticket(estado);

-- Для поиска активных назначений техника
CREATE INDEX idx_asignacion_trabajador_activa ON Asignacion(trabajadorId, estado);

-- Для поиска по ключу (clave)
CREATE INDEX idx_consumo_clave ON Consumo(clave);
```

### 16.10.3. Обновление схемы БД без нарушения транзакций
(Actualización del esquema de BD sin romper transacciones)

```sql
-- 1. Добавить новую колонку с DEFAULT (не требует блокировки)
ALTER TABLE Ticket ADD COLUMN prioridad INTEGER DEFAULT 3;

-- 2. Создать índice CONCURRENTLY (не блокирует запись)
CREATE INDEX CONCURRENTLY idx_ticket_fecha ON Ticket(fechaCreacion);

-- 3. Добавить внешний ключ (проверить данные сначала)
ALTER TABLE Consumo ADD CONSTRAINT fk_consumo_material 
FOREIGN KEY (materialId) REFERENCES Material(id);
```
